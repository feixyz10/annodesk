## 1. 产品目标

面向图像数据集的本地优先标注工具，支持检测框和实例分割。从纯图片开始标注，或直接打开 Ultralytics YOLO 框数据集，以 SAM 按框预分割，再人工修改与复核。工作台支持英文和简体中文，采用浅色 Web 界面；未来可复用前端以 Tauri 包装客户端。

支持单机运行及前后端分机部署。首版不做账号、权限、TLS、多人协作、视频、训练。前后端分机指独立托管网页；数据集读写和推理始终在API电脑。用户在本机浏览器访问服务器serve即可远程使用，不要求本机运行ui。本地项目读写、逐图上传图片和提示到远端推理节点并返回mask/框的模式尚未实现，应作为后续独立能力设计。

## 2. 技术与仓库

- 前端：Vue 3、TypeScript、Vite、Pinia、Naive UI。Konva 管理框、提示点与选择；独立 Canvas 显示 mask，使用同一图像坐标变换。
- 后端：Python、FastAPI、Pydantic、Uvicorn；业务日志采用 Loguru；CLI 使用 tyro，通过类型化配置生成子命令，不自写 argparse，不使用 Typer。
- 模型：可替换适配器，首批目标为 SAM 2.1、MobileSAM、SAM 3；按能力启用正负点、框、文本。SAM 3 文本与视觉提示分开调用，不假设所有 SAM 衍生模型接口相同。
- 项目根是一个 uv 项目、一个 Python distribution，名称/import/命令统一为 annodesk。使用 src/annodesk、frontend、tests、docs/specs。
- uv sync 安装 Python 环境；uv.lock 固定依赖。Python 基准采用当前已配置的 3.13，基础标注服务验证该版本；推理依赖如不兼容，明确要求另选受支持 Python，而不悄悄更改用户解释器。
- Ultralytics为主依赖，标准安装同时提供检测与分割的推理运行库，不再提供inference extra。模型依赖保持lazy import；帮助、UI和纯几何操作不加载Torch或模型。仅随包提供本项目显式收录的YOLO11n默认检测权重及原始来源/许可说明；SAM等其他权重不随wheel发布，uv sync不下载权重。
- Python 用 ruff format、ruff check（E/F/I/UP/B）统一格式与检查；每次代码提交前执行。领域/存储/API 用 pytest，前端用 vue-tsc、Vite 构建及关键交互验证。
- Git 跟踪源码、测试、锁文件、正式设计及必要 README；忽略计划、执行记录、旧草案、截图、交互原型、环境、缓存、其他模型与用户数据；assets/models/yolo11n/为明确随包发布的权重例外。

## 3. 工作项目与路径

标准布局：

```text
dataset/
  images/[train|val|test]/任意多级目录/image.jpg
  labels/对应相对目录/image.txt          # detection
  labels_seg/对应相对目录/image.txt      # segmentation
  data.yaml
  .annodesk/
    project.json
    annotations/对应相对路径/image.jpg.json
    masks/实例UUID/版本.png
    operations/
    trash/
```

不要求 train/val/test 齐全，也不要求目录必须取这些名字。图片可以直接位于 images 下；平铺/多级目录均可。标签相对路径必须镜像图片目录。图片支持 jpg/jpeg/png/webp/bmp/tif/tiff。

坐标统一以Pillow解码得到的首帧RGB栅格为准：JPEG不额外应用EXIF旋转（原始120×80、Orientation=6仍为120×80），TIFF使用Pillow自身解码后的栅格及尺寸；不变换已有框/mask坐标。修复不会自动推断并纠正此前因显示错位产生的标注，受影响图片仍需人工复核。服务端尺寸、主画布PNG预览、缩略图、SAM单掩码/候选与检测推理共用此栅格。推理传连续BGR ndarray，避免Ultralytics/OpenCV再次按文件元数据处理方向。/images/{id}/file提供无EXIF的全分辨率PNG预览，而不是原始文件字节；首帧、RGB/8bit显示，不承诺TIFF多页或高位深编辑。

项目源图片不改写。导出TIFF、带非1方向标记或动画的图片时，生成无方向元数据的首帧PNG副本，同步YOLO图片列表及COCO file_name/尺寸，标签坐标保持不变；普通静态图片继续复制。避免训练工具再次旋转原始EXIF图片而错配标签。

提供两种入口：打开数据集根（识别 images 和可选标签），或打开任意纯图片目录（项目记录图片根映射，不移动原图）。后端处理本机路径，浏览器不把客户端路径误当作后端路径。

同目录同 stem 不同扩展名会映射到同一个 YOLO txt；导入必须报告冲突，不覆盖。非法标签行、类别越界、尺寸异常应展示具体文件、行号和原因，不能静默丢弃。检测标签在首次物化前校验转换后的实际框边界与正面积，而非只校验归一化各分量；与保存共用最多max(width,height)×1e-6像素的舍入容差，仅将容差内边缘误差裁到图内，真实越界拒绝写入内部记录。检测导出也拒绝旧记录中的真实越界框，不把非法框传入训练标签。没有 txt 不等于人工确认背景。

data.yaml 可缺失。扫描已有类别数字 ID 时生成 class_N 占位名；新增类别自动维护 names 和项目类别表。未划分数据允许标注，不伪造 val/test；训练导出前再完成划分校验。

内部 JSON/无损 mask 是完整编辑记录；两个 txt 目录是同步的 YOLO 投影。首次从 txt 初始化；读取、解析及首次物化均持项目RLock，初始化落盘前复查内部记录，若已存在则返回已提交记录，绝不以旧revision=0覆盖。mask GET为只读，即使返回404也不创建内部标注。之后检测外部修改并明确要求重新导入/冲突处理，不自动覆盖用户外部修改。

保存时由有效RLE重建多边形投影，修复旧记录中过期的polygons缓存，不接受与同一mask相矛盾的传入polygons；导出从RLE重建投影，兼容缺少polygons的旧记录。RLE-only实例不能因没有多边形缓存而被导出为空背景。

## 4. 实例和分类

每个实例有稳定 UUID、类别 UUID、可选显式 box、可选 mask、来源、提示历史和模型标识。box-only、mask-only、box+mask 均合法。数字 class ID 只用于序列化。

- Draw box：产生显式检测框，可拖动、四角/边缩放、数值调整、键盘微调、改类、删除、隐藏、锁定、撤销/重做。限制图像边界，禁止零面积或非有限坐标。
- Box prompt：框只是分割提示，默认只保存 mask。正负点或文本分割也不自动创建 detection box。
- 从已有检测框生成 mask：关联原实例、继承类别、保留框。调整框后关联 mask 标需复核，提供按新框重算；不静默覆盖人工 mask。
- 选中已有实例加正负点，接受后替换同一实例 mask；不新增重复对象。重启后可从提示历史重建，不依赖持久化 logits。
- SAM 3 文本可返回多个实例；先指定类别和提示词，预览后接受。中文类别名称允许；不承诺模型中文提示质量。
- 删除操作区分仅 box、仅 mask 和整个实例；按当前明确的几何选择执行。无损 mask 保留孔洞和不连通部分，投影多边形不作为唯一数据。

交互式单掩码：添加或删除正负点、完成/调整分割提示框后，防抖自动更新所选实例，无需点击Segment current；保留Refine mask作为显式重试。推理先读取已保存提示的只读单掩码预览（multimask_output=False），仅在项目会话、图片、实例、模型参数、revision及编辑代次仍匹配时合入本地并自动保存。每客户端最多一个提示/候选推理请求在途，连续编辑只排队最新提示；切图、切工具/模型、普通编辑或进入候选模式丢弃旧响应。失败保留现有mask并给出可重试信息。候选模式内提示变化仍生成多候选，不同时触发单掩码。

工具栏分成标注结果组（Detection box）和SAM提示组（正负点、SAM box prompt、文本），提示框图标采用角框加中心提示，不使用检测矩形图标。检测框为类别色实线，SAM提示框为固定琥珀色虚线，选中控点也使用对应颜色。选择工具的选择范围默认“标注结果”，此时仅检测框/掩膜命中，点和提示框不能拦截；切到“SAM提示”后，仅提示命中，结果不能拦截。框的命中显式禁用填充，仅8屏幕像素宽的边缘参与命中，不能以Konva默认空心视觉推断内部不命中。无关图层不参与命中检测，仅明确选中的几何显示变形控点。控点的指针事件不参与画布的选择/绘制判定，拖动控点时不得因事件冒泡清空选择。右侧实例属性按“标注结果 / SAM提示”分组提供检测框、mask、提示框直接选择按钮，无论三者是否重叠，都可指定目标；切换目标不更改标注。

选择工具切到SAM提示范围后可选中单个正负点或分割提示框，X/Delete删除选中的提示；框边缘选中显式框后只删除框，点击mask内部选中mask后只删除mask。实例列表选择整对象时才删除整实例。右侧提供删除选中提示、清空分割提示和删除整个对象的独立入口。删除提示保留mask、显式检测框及类别；有剩余提示时自动重算，无剩余提示时保留现有mask且不推理。提示编辑和删除可撤销。Segment current仅补全缺失mask，无待处理实例时显示状态提示，不报“请选择对象”。宽度小于800px时提供图片详情按钮，以可关闭的侧边面板访问实例操作，不直接隐藏且失去入口。

连续标注通过新物体按钮或N结束当前实例选择，保留已有数据并取消旧预览/在途自动结果。分割模式保持框提示工具，其他工具切到正点；检测模式切到画框；首次绘制时才创建新实例，不保存空实例。未选中实例时正点创建新对象，已选中时继续细化同一对象。Shift+X或Shift+Delete删除整个实例及其mask、检测框、提示，可撤销；X/Delete仍只删当前明确选择的几何或提示。清空提示一次移除全部正负点及提示框，不运行推理、不删除或改变现有mask/显式检测框。

画布上方仅保留48px单行模型/当前图推理/自动处理及平移缩放工具，不预留对象操作区。右侧上部为实例列表与选中行内操作，下部常驻图片属性，取消Object/Image页签。上部默认55%高度，可拖动/键盘调整25%–75%，双击复位，两部分分别滚动。实例行采用固定列：类别/序号、框、mask、SAM、显隐、锁定、更多、展开；缺失几何保留灰色不可点击占位，不移动后续列、不隐式创建几何。名称选中并展开实例，再次点击同一名称切换展开/收起且保留选择；几何图标直接选中目标并展开；显隐/锁定不改变当前选择，展开箭头可收起但保留选择。一次只展开当前实例；行内包含可搜索类别选择、细化/候选、清空提示、提示详情、mask转框及折叠的坐标/外扩、目标删除与单独的整实例删除。提示详情允许选中提示框和每一个正负点。更多与右键共用同一菜单及禁用规则，菜单绑定图片/项目会话/实例，切图或切换选择后失效；菜单打开时快捷键不得误切图片或关闭整个窄窗口侧栏。选择、展开、过滤和反馈不改变画布尺寸。图片属性包含审核、tags、备注、确认无目标与清空本图提示。“清空本图提示”一次移除当前图所有未锁定实例的全部点及提示框（含隐藏实例），保留检测框、mask和锁定实例；移除已无几何的提示草稿。单次撤销恢复全部清理，不自动推理，在途结果作废；纯提示草稿恢复不使Detection审核失效。

选中的mask基于无损栅格边缘，以蓝色描边及白色外描边突出外轮廓、孔洞及断连部分；只缓存当前选择的轮廓，按缩放调整描边宽度。

mask选择按无损覆盖层的alpha像素命中，孔洞和背景不命中，断连部分仍属于同一实例；RLE-only记录不依赖polygon缓存才能选中。命中缓存随图片/项目/revision淘汰。polygon-only旧实例按多边形内部命中。选择框、mask、提示和整个实例有独立目标；删除一个几何保留另一几何、类别和提示，只有没有剩余几何/提示时移除空实例；审核仅失效对应任务。

类别面板常驻左下。没有选中实例时，显示 Default for new annotations: <class> 并设置新对象默认类别；选中实例时显示 Class for selected object(s)，点击类别改类。Default class 按钮明确取消选中，并以 tooltip 解释它只设置后续标注的类别。多类别支持搜索、最近使用和收藏；未分配类别草稿允许存在，但完成/导出前必须解决。

## 5. 类别、tag、颜色

类别支持新增、重命名、颜色编辑、删除；新增分配递增 ID，不复用已删除 ID。删除仍被引用的类别必须选择改派或删除实例。内部身份始终不变，ID 空缺在工作配置中保留占位。

类别和tag各自要求非空且表内名称唯一，跨表允许同名。改名前完成校验，元数据写入失败时回滚内存字典，不能由后续成功写入意外提交被拒绝的改名或新增项。

提供一键连续编号，先预览旧/新 ID 映射和影响数量。获得项目写锁，暂停推理写入，更新当前项目 labels/**/*.txt、labels_seg/**/*.txt、data.yaml 和内部映射。只改标注行首 ID，不改坐标、图片路径清单或历史导出副本。全量预校验、备份、事务日志和启动恢复保证多文件一致；不把多次 rename 称为跨文件原子操作。

class 与自由 tag 分别管理调色板，采用同一策略：默认建议颜色，可手动改色；新颜色尽量远离同一调色板已用色。在 OKLab 中从明度/色度适中且落在 sRGB 色域的候选中，最大化到已有色的最小感知距离。不能用简单 RGB 距离替代，也不能保证无限类别仍可区分。

颜色绑定稳定 UUID，存项目字典；重命名、ID 重排和新增项不改变旧颜色。手动颜色过浅/过近时提示并提供替代色，但允许保留。颜色外保留名称、实例编号和选中描边；tag 用淡背景、色边、深色正文。状态色固定，不作为可编辑 tag 色。

## 6. 图片状态与清理

Detection 和 Segmentation 分别记录复核状态，图片另有全局使用状态。英文展示：

| 展示 | 内部含义 | 颜色 |
| --- | --- | --- |
| Not reviewed | pending，尚未检查 | 灰 |
| Approved | ok，人工确认 | 绿 |
| Needs review | uncertain，有疑问/发现问题 | 琥珀 |
| Excluded | excluded=true，排除使用 | 低饱和红 |

Excluded 优先显示但保留原复核状态，不等于删除。blurry、night、occluded 等是自由多选 tag，可新增、改色、备注、筛选、批量设置。

自动保存、自动分割不会变 Approved。修改已通过的任务标注使其回 pending；关联框变化使 mask 需复核，改 mask 不使独立检测框失效，共享类别变化影响两任务。Needs review 保持至人工明确处理。

清理 Excluded 前显示具体图片及标签数量，一起移入项目回收站，记录原路径，支持恢复；恢复按内部类别UUID与当前数字ID重建两类YOLO投影及指纹，不直接沿用回收期间重排前的标签ID，也不自动恢复已删除类别；永久清空单独操作。当前API在批处理或导出仍为running时拒绝移入回收站及恢复，返回409；请求取消但worker尚未结束时同样拒绝。检查与文件操作持有和启动/恢复任务相同的管理锁，避免检查空闲后并发启动的竞态。默认批处理/训练导出排除 Excluded 和 Needs review，pending 是否导出由设置决定并显示计数。

## 7. 工作台布局

顶部以间距和细分隔线分组：左侧项目/Open与Classes/Tags；Batch/Export为处理组；Tasks/Logs为右侧任务诊断组；最右侧为快捷键帮助图标。Tasks按钮预留状态宽度，运行中的数字与旋转标识在按钮内部，不推动邻近按钮。当前图操作随Detection/Segmentation切换，模型入口打开居中设置窗；Reload等详细设置移入该窗。顶部工具栏下增加常驻项目审核统计栏，详见 §10.3。
左侧上方：图片搜索、状态筛选、Tree/Flat 文件列表；下方：常驻 Class palette。
中间：标注工具、模型选择/自动分割、主画布、文件与比例、横向缩略图带。
右侧：上部实例列表固定列对齐，选中行展开全部实例操作；下部常驻图片属性，上下分隔条可拖动。不得混放全项目类别表。

左右分隔条可拖动，中心取剩余空间；默认左260px、右340px，最低左190px、右300px，保护中央可操作宽度。左侧上下也能拖动，分隔条支持键盘小步调整、双击复位。布局、语言和本地API覆盖的localStorage读写统一捕获访问getter及方法异常；存储缺失、SecurityError或写入配额不足不阻止初始化和拖动。读失败使用默认布局/语言及服务端ui-config.json指定的API（未指定时同源/api/v1），当前页面调整继续生效，只不保证刷新后保留。正式版记忆用户布局，窄窗口折叠侧栏，不强行压缩画布。

Tree 保留 images 下多级子目录，支持逐目录展开/收起、Expand all/Collapse all；Flat 展示文件名和相对父目录。折叠只影响树内可见行，不改变过滤序列；模式切换不改变当前图片。搜索匹配文件和路径，暂时展开匹配目录，清空后恢复。

实例列表与画布双向选择同步，包含短 ID、类别、Box/Mask、锁定/可见、推理和复核标记。Classes/Tags 窗口仅管理项目字典，名称和颜色使用独立编辑草稿，不直接v-model绑定项目字典；提交期间禁用该行输入，后端成功后才应用返回的规范化名称/颜色，失败恢复已提交值并显示错误。切项目或卸载后丢弃旧请求响应。类别下拉与常驻面板允许快捷新增。

## 9. 缩略图和内存预算

横向缩略图可滚轮、触控板、拖动滚动条和左右按钮滚动。滚动不切图；明确选图才保存/切图。切图将当前项滚入可见区域，编辑状态/tag及普通同session元数据刷新不重置手动滚动。搜索和项目上下文改变时同步重置缩略图带scrollLeft与虚拟起点；结果收缩时限制两者，空结果不得保留巨大占位。过期的异步居中回调不得把新筛选恢复到旧偏移。

- 虚拟列表，可见区两侧各预取3张，最多24个挂载节点；不是只给全量 img 加 lazy。
- 最大4个并发请求，窗口外待发任务丢弃，过期请求取消/响应丢弃。
- 应用解码 LRU 最多48张或24MiB，任一上限触发淘汰并释放引用/bitmap/Object URL；不声称可限制浏览器总内存。
- 按显示尺寸/DPR 请求，最长边上限320px；不向预览带传原图。
- 后端缩略图磁盘缓存默认512MiB，可配置。按内容指纹、尺寸和生成版本失效。
- 原图仅当前图按需加载，可预取下一张适当预览；超大图后续可扩展瓦片。文件列表虚拟化或分页。搜索、展开/折叠、Tree/Flat切换和项目上下文改变时同步重置虚拟起点与容器scrollTop；结果收缩时限制滚动位置及起点，非空列表不得因旧偏移显示空白。普通同session元数据刷新保留滚动和展开状态。

## 10. 保存、并发和任务

编辑操作结束后短延迟自动保存；切图前强制提交并等待成功。失败保留当前编辑、显示重试，不带错切图。关闭页面有未保存内容则提示，不能指望 unload 完成写盘。

手动检测框坐标编辑、拖动和缩放共用锁定/边界校验及撤销入口；改变带mask的框时保留mask并将Segmentation标为uncertain，mask转框几何操作仍遵守其独立语义。普通交互式分割成功后保留撤销快照。画框/提示框及框移动、变形绑定手势开始时的项目session/UUID/根目录、图片、工具和标注上下文代次；切图、开始导航、项目或工具变化、标注记录替换时同步取消，提交前再次验证。即使A→B→A或工具切换发生在同一渲染周期，旧手势也不得产生新实例、改框、撤销快照或自动保存。当前图mask覆盖缓存随revision淘汰旧版本，晚返回的旧版本/旧项目覆盖层不得重新进入缓存；图片加载使用请求代次，切走再切回同一图片、项目切换及卸载后同样拒绝旧响应。

使用 revision 乐观锁及单写入会话，阻止多浏览器覆盖。保存内部记录、mask 和两类 txt 投影，以临时文件+原子单文件替换+操作日志恢复多文件一致性；全部完成才显示已保存。删除最后一个标注写空 txt，不残留旧标注。缺少标注与 explicit_empty 背景标记分开。

项目API元数据增加仅运行时的session，打开不同目录或重启后更新，不写入项目元数据文件；复制项目即使UUID相同也不共享session。工作台JSON请求携带X-AnnoDesk-Project，原图/mask/缩略图URL携带project_session；服务端在访问项目之前拒绝过期上下文并返回409。/project和/models仍允许读取当前上下文用于发现。协议1的无上下文API调用保持兼容，但调用者须显式携带session才能获得跨项目防误写校验；session不承担认证功能。

项目请求登记期间不允许切换并释放原写锁；切换期间拒绝新的项目请求，后台批任务仍受既有运行检查保护。页面切图/打开项目期间暂时停止工作区交互，避免晚编辑被替换。元数据、类别响应和媒体缓存同时按session隔离，不能仅依赖可能被复制的项目UUID。普通刷新不能自动接纳不同session并沿用旧标注，必须经显式打开项目建立新上下文。模型配置初始化失败也必须立即释放写锁，不依赖垃圾回收。

所有推理绑定 project/image/instance/prompt revision/model/job ID；过时结果不能覆盖人工编辑。当前图分割、检测和mask转框在进入执行队列前冻结标注revision、提示、请求参数、图片及外部标签指纹，执行前与提交前均校验；排队期间的人工保存使旧请求冲突失败，不能在出队时读取新revision来覆盖人工结果。后台批任务不依赖浏览器连接，完成逐图持久化，支持取消、失败重试、续跑；只在推理调用边界响应取消。

前端推理、几何处理、候选应用及当前图刷新按切图代次丢弃过期响应；切走再返回同一图片不能复用旧请求，较低revision的响应也不能回退当前结果。保存前等待期间发生切图时不再向新图片提交原操作。空列表或全零mask推理输出报错并保留已提交标注；成功生成非空mask时清除Segmentation的explicit_empty。未分配类别只影响YOLO投影，仍须通过检测框、分割提示框、polygon和mask尺寸/编码校验。项目元数据刷新也校验当前项目与切图代次；过期候选应用不能使候选条永久停在应用中。

多文件保存中途失败后保留pending.json，并阻止后续项目写入、回收站操作和导出覆盖或使用未恢复状态。提示重启后端，由启动恢复重放原事务；不能用一次后续元数据保存替换尚未完成的恢复日志。

当前图、全部图、切图自动分割共用任务接口。默认只处理有框且无 mask 的实例，跳过 Excluded，不重算已编辑 mask。无框不自动猜目标/全图分割。交互请求优先，SAM 编码按图像指纹/权重/预处理缓存并有内存预算。

API 使用单 Uvicorn worker；模型由受控后台执行单元持有，推理不阻塞 HTTP。本地模型加载失败仍允许框标注。开始构造新的SAM predictor前清空predictor、模型键、图像缓存键及loaded_id，只有新predictor完成setup_model后才一起提交predictor和键；构造器、官方权重构建器或setup失败均保持空缓存，允许重试该模型或重新加载原模型。模型窗口加载失败后重新读取后端实际加载状态，避免残留Loaded提示。模型适配器提供 capabilities、load/unload、encode、segment_visual、segment_text，结果不直接写 UI 状态。

### 10.1 多进程推理与设备分配（0.2.0）

CLI segment 与页面 Batch 共用执行层。当前图交互分割保留独立串行通道，不等待整个批次完成；不抢占在途图片，也不保证独立模型在同一GPU上具有硬件调度优先级。不在多个进程之间分拆同一图像的提示。

| 参数 | 取值 | 默认与约束 |
| --- | --- | --- |
| --device-type | auto、cuda、cpu、mps | auto 按 CUDA → MPS → CPU 选择；显式类型不可用报错 |
| --devices | auto 或逗号分隔逻辑编号，如 0,1 | CUDA 默认全部可见设备；CPU/MPS 只接受 auto |
| --num-workers | auto 或正整数 | auto：CUDA 每个选中设备1个，CPU/MPS 为1个 |

--model 仍为 models.json 中的 ID，不是权重路径。UI、CLI 共用 ModelRegistry：先选择 ID，再解析 source 目录和兼容权重，禁止自动下载。运行时设备参数放在 CLI/任务配置，不混入模型目录字典。

CUDA_VISIBLE_DEVICES 由启动环境设置，程序不覆盖它。--devices 使用该环境过滤和重排后的逻辑编号；例如 CUDA_VISIBLE_DEVICES=2,5 配合 --devices 0,1，分别对应被暴露的原始设备2、5。记录原环境值与逻辑编号映射，不将逻辑编号再次当作宿主机编号解析。device-type=auto 配合数字设备列表时要求 CUDA；不可用则报错，不忽略该列表。拒绝重复、负数、越界或空项。只在 auto 且 devices=auto 时允许硬件选择回退；模型推理失败不自动回退到 CPU。

worker 采用 spawn 进程，各自绑定一个设备、常驻一份模型并维护当前图像编码。设备探测使用隔离的短生命周期探测进程；协调进程不创建 CUDA 上下文。每个 worker 的设备在加载模型前确定，通过显式 device 参数传入适配器。协调器按空闲 worker 动态派发，每个 worker 一个容量1的收件箱；避免共享队列在进程退出前未报告领取状态时无法确认任务归属。不把图片静态切成每卡固定份额。所有框以整张图为一个任务，复用该图编码。

W 个 worker 依次分配给 D 个设备，worker i 绑定 devices[i % D]，各设备 worker 数差不超过1。W<D 时只有前 W 个设备被使用，启动计划明确列出闲置设备；W>D 允许同设备多个模型副本。默认每卡1个，不承诺增加同卡进程会提速；MPS 多进程需真实设备验证。CPU worker 按可用 CPU 数量分配线程预算，限制 PyTorch/BLAS/OpenCV 的嵌套并行，避免进程数乘线程数失控。

协调进程是唯一项目写入者：获得跨进程项目写锁 → 读取标注快照 → 派发纯计算任务 → 验证 image/instance/revision/外部指纹 → 事务保存 → 记账。worker 不构造具有写入副作用的 Project，也不直接改 txt、内部标注或统计索引。项目锁同时约束独立 UI 后端和 CLI；不能只靠进程内 RLock。同一项目第二个独立写入者直接报冲突。

启动前冻结模型配置、权重stat指纹（mtime_ns与大小）、设备计划和图像范围；所有 worker READY 后才派发图片。每个 worker 同时最多持有1张图，总在途最多W张，每个收件箱最多1张，低于原定2W张等待上限，结果队列最多W张，协调进程交错派发/收集/保存，不能先塞满全部任务再收结果。主进程独占结果提交；工作线程只能返回 CPU/RLE 数据，不跨进程传 CUDA tensor。每张图最多一个在途任务，只有保存成功才增加成功数。

缺失模型、设备无效或模型加载 OOM 属于启动失败，不生成“全数据集逐图失败”噪声。批次开始冻结image_id→相对路径，并随报告持久化，恢复继续使用冻结路径。单图错误、成功结果和worker崩溃日志不依赖仍存在的entries；外部移除在途或待处理图片时记录该图片失败并继续其他图片，旧报告缺少路径且图片已不存在时以ID作为诊断后备，不因KeyError中断整批。单图错误记入报告后继续；worker 崩溃时回收其未完成任务，最多重新派发1次，记录尝试次数，禁止无限重试。所有 worker 不可用则停止。首次 Ctrl+C 停止派发并收尾；再次 Ctrl+C 强制终止，未提交结果不计成功，重跑按既有 mask 跳过已完成工作。退出码：0成功，1有图片失败，2配置/启动失败，130用户中断。

.annodesk/segment-report.json 记录模型/权重标识、选中设备、worker 分配、逐图结果及耗时；不把某个 worker 的存活状态作为恢复依据。页面任务保存相同的执行计划与结果口径，设备/并发参数是每个 job 的快照，运行中修改模型配置不影响在途任务。

### 10.2 Loguru 日志与页面 Logs 窗口（0.2.0）

增加基础依赖 loguru，统一应用业务日志及标准 logging/Uvicorn 错误。serve、ui、segment 每次进程启动建立独立日志会话；--help、docs、doctor、models list 不因查询而创建日志文件。默认位置严格为 ~/.cache/annodesk/{datetime}.log，不采用 macOS 的 ~/Library/Caches 替代路径。datetime 使用本地带微秒的安全文件名，如 2026-10-22_114203_123456.log，排他创建避免多个实例撞名。相对日志目录以命令启动目录解析。

新增运行时 --log-dir 和 --log-level，默认目录如上、文件/终端级别 INFO；DEBUG/TRACE 必须显式启用。正常运行不得重复初始化 sink。默认20MiB轮转、保留14天；启动时也清理过期的本软件日志文件，不动模型及其他缓存。文件以 UTF-8 无 ANSI 输出，格式：

```text
2026-10-22 11:42:03.127 +08:00 | INFO     | Model ready: sam2.1-small; device=cuda:0; workers=3
```

默认前缀不包含源码文件名、函数名和行号。错误堆栈写文件，禁用异常局部变量展开（diagnose=False）；页面只接收经过整理的错误摘要和业务上下文，不显示 Python traceback。图片相对路径属于业务信息，可以显示。禁止记录 token、完整环境变量或未经筛选的凭据配置。文件不可写时只发出一次明确警告，回退终端与内存事件，不因日志目录问题丢失标注。

多进程下由协调进程独占 Loguru 文件 sink。worker 的 READY/启动失败/单图结果通过有界结果通道传回，主进程生成结构化业务事件，统一分配会话内递增 sequence 和接收时间。worker 本轮不产生逐框诊断流，因此不额外建设第二套日志队列；将来需要高频诊断时再增加独立有界队列，不能阻塞或丢弃错误结果。结果通道容量W，日志环形缓冲2000条。日志 sink 内不再次调用 logger；正常退出停止 worker 后关闭 sink；文件不可写不影响保存。

日志分为业务重要事件和诊断事件，是否进入 UI 由结构化 ui_visible 标记决定，不只按等级猜测。页面默认展示：

- 配置/模型解析摘要、模型加载成功/失败及有效模型 ID。
- 设备类型、可见/选中设备、worker 分配及 READY 汇总；大型 worker 池不逐 worker 刷屏。
- 项目打开/锁冲突、批任务开始、取消、恢复、完成及整体成功/失败摘要。
- 保存/推理/设备/导出错误及可操作的原因。

正常 HTTP GET、统计/任务轮询、每次 autosave、逐图成功和每个框的推理细节不进入页面。逐图诊断为 DEBUG；HTTP 正常访问降为 DEBUG，日志读取/stream 端点不产生访问日志，防止自我放大。主任务成功完成用 SUCCESS；可恢复问题 WARNING；单图失败 ERROR；服务/执行器不可继续用 CRITICAL。

页面同类错误按 project/job/event_type/error_code 聚合：首次立即展示，10秒窗口结束再发送一条带新 sequence 的合并摘要，含额外重复次数及最后一个图片示例，不修改已发送事件；摘要的 repeat_count 不重复计算首条。文件和逐图报告仍保留每次原始失败记录。聚合是展示层行为，不能改变失败计数。批处理进度由任务组件展示，不每张图片生成一条页面日志。

Logs 入口常驻，未打开项目也可查看服务启动/模型配置错误。窗口默认宽640px，可拖动，窄屏最大占满窗口；日志区使用等宽数字和自然换行，内容为“时间 | LEVEL | 详情”，没有 logger 源码来源列。默认 scope 为当前项目（进入页面时尚无项目则为 Service），项目筛选包含全局服务事件，可切换 Service / Current project。

筛选由一个等级下拉框和 = / ≥ 切换组成，默认 ≥ INFO。页面等级提供 INFO(20)、SUCCESS(25)、WARNING(30)、ERROR(40)、CRITICAL(50)。= ERROR 只显示 ERROR，≥ ERROR 包含 ERROR 和 CRITICAL；使用数值严重度比较，不按字符串排序。切换条件重新查询近期匹配记录，不只是过滤当前屏幕。DEBUG/TRACE 诊断留在文件，本轮不加入页面等级菜单。

提供 Pause live / Resume、自动滚动开关、Clear view 和下载当前日志。暂停关闭 stream 并保留游标，后台任务与写盘继续；恢复时按游标补取可用记录，超过保留窗口明确提示 gap，不在浏览器无限积压。Clear view 只重置该页面的显示起点，不删除日志文件。复用数据表/列表虚拟化，最多缓存1000条事件、挂载约60行，长文本折行，单条页面 message 最多2000字符并标明截断，完整信息留在文件，保持滚动位置。提供复制当前视图。每行正文可悬停查看完整UI摘要。窗口关闭时断开该页面的日志 stream，不改变记录行为。

GET /api/v1/logs 返回最近最多200条匹配记录（limit 上限500）、session_id、next_cursor、gap；GET /api/v1/logs/stream 通过 SSE 发送后续事件。两者支持 scope/project_id、level、comparison=eq|gte。过滤后的 next_cursor 为已扫描的最新序号，不能因无匹配事件停滞。记录结构至少包含 session_id、sequence、timestamp、level_name、level_no、message、event_type、project_id、job_id、worker_id、device、repeat_count。

服务内存仅保留最近2000条 UI 重要事件；游标以(session_id, sequence)唯一。SSE 断线续传和切换筛选不重复追加，15秒心跳，服务重启或超出缓冲区时发出 reset/gap，页面明确提示“部分实时日志已过期”，不伪装完整历史。首次 tail 查询快照与 stream 游标连贯，切项目或切筛选时丢弃旧连接响应。

下载接口仅允许当前日志会话的文件，不接受任意文件路径。当前阶段页面展示本服务会话及其 worker 日志，不自动聚合另一个独立 CLI 的实时日志；独立 segment 的日志在其会话文件中查阅。历史会话浏览可后续扩展。远端部署时文件路径位于后端电脑，浏览器通过 HTTP 获取结构化事件和下载文件，不读取客户端 ~/.cache。

### 10.3 常驻项目统计与批处理进度（0.2.0）

现状：0.1.0 只有 Batch 窗口中的任务完成数，没有常驻项目审核汇总，且旧 completed 含跳过和失败。本次分离“人工审核状态”“模型任务执行进度”，自动分割成功不能变成 Reviewed 或 Approved。

在顶部主工具栏与三栏工作区之间增加一条紧凑统计栏，横跨工作区，不挤占 Class palette；显示当前任务名、Approved/总数和四个状态计数，同时常驻显式框与mask数量及“更多统计”入口。与右侧 detection/segmentation 切换同步；默认统计整个项目，不随图片列表搜索/滚动变化。窄屏可换两行，所有计数仍可见。

示例：

```text
Segmentation · Approved 65/100 · Not reviewed 20 · Approved 65 · Needs review 10 · Excluded 5
```

常驻汇总只使用Approved数量作为分子，当前项目总图片数作为分母，不合并Needs review或Excluded。若只有自动分割完成但无人确认，仍是Not reviewed，不增加已通过分子。两类任务各自统计，Excluded 为全图共享。空项目显示 No images，不显示 NaN 或0/0百分比。

四项使用排他展示分类：先判断 excluded=True，属于 Excluded；否则按当前任务的 pending/ok/uncertain 分配至前三项。因而四项相加严格等于 total。只改变统计归类，不覆盖底层原审核状态；取消 Excluded 后恢复到之前的审核分类。无内部标注记录的图片默认为 Not reviewed，只有 YOLO 标签或 mask 也不能视为已复核。四项不是任意多选 tag 的累计计数，普通 tags 不参与该进度。

显示的是已提交状态，不把尚未保存的编辑计入服务端统计；保存成功后立即刷新，失败则保留原计数并显示现有保存错误。自动推理使已通过状态回到 pending 时同步扣减。移入项目回收站的图片不再计入总数，恢复后重新计入。Excluded 未移入回收站时仍计入总数。

GET /api/v1/project/statistics?task=detection|segmentation&include_excluded=false 返回 total、counts{pending,ok,uncertain,excluded}、reviewed、statistics_revision、status=indexing|ready，以及boxes、masks、instances、classes和invalid_images。classes每行包含class_id(UUID/null)、数字index、原始name/color、boxes/masks/instances/images；未分类及未知类别单列，项目中未使用类别保留0行，images按类别去重。实例同时有显式box和mask时分别计数，mask同时含RLE与polygon只算一次；SAM提示框不算检测框，仅提示草稿计入instances。几何统计默认排除excluded，窗口toggle控制是否包含；审核状态计数及分母始终覆盖全项目，不受该toggle或图片列表过滤影响。

统计来自可重建SQLite缓存，存两任务审核状态、excluded、文件变更戳、按图片/类别聚合的几何计数与无效记录标记，不存mask像素。启动异步核对/补建；内部JSON存在时以其为准，否则只读解析YOLO labels/labels_seg，不创建内部记录、不打开图片或解码mask、不加载模型。无效标注不冒充0个真实标注，几何计数跳过该图片并在界面显示invalid_images警告。首次扫描完成前显示Loading statistics。缓存损坏可重建，缓存写入失败不得回滚已提交标注。

“更多统计”居中窗口默认表格，支持切换并列水平柱状图、类别名称/ID搜索；按boxes+masks降序。表格显示类别、去重图片数、实例、框、mask；图中两种几何使用固定不同颜色和数值，所有筛选结果共用比例尺。表格每页50类、柱状图每页20类，限制渲染数量，切换视图/搜索重置页码。长类别名及中英文布局可换行，未分类/未知类别为UI文本，真实类别名保持原文。

唯一写入协调进程在事务提交后更新索引和内存汇总，缓存无法更新时标记索引过期并后台重建。恢复日志、重排、导入、排除、回收站操作也走相同失效流程。统计接口不每次全量扫描，支持大数据集。前端保存成功后主动拉取；后台 job 运行时每2秒刷新，浏览器隐藏时暂停，回到前台立即同步。无后台 job 时每10秒检查更新；并发响应按项目/task与请求generation丢弃过期数据；statistics_revision仅为当前索引生命周期内的更新计数，不能跨后端重启比较大小拒收最新请求。

Tasks 窗口和工具栏中的轻量活动任务入口使用独立口径：启动快照含 input_total 张图片，预检查跳过 S 张，需要处理范围 T=input_total-S 张（含预检查失败）。显示“Batch: F/T finished · A succeeded · B failed · S skipped”，其中 F=A+B。运行中 worker 仅完成计算但主进程尚未保存的结果仍算在途，不算成功。当前进度条为 F/T，不把跳过当作模型推理成功；T=0 显示 No images require segmentation。取消/中断的剩余量单列，任务错误不能让进度显示“全部成功”。

例如项目共100张，25张已有mask/不符合任务条件；需要处理75张，58张成功、2张失败时显示“60/75 finished · 58 succeeded · 2 failed · 25 skipped”，仍有15张待处理。机器进度与上方已通过计数互不替代。预检查遇到损坏输入要记为可见失败，并纳入 T、B 和 F，不再派给 worker，不能静默归入 skipped；报告给出具体原因。恢复同一 job 保留原任务快照和计数，重新运行新 job 则重新计算待处理集。

#### 任务窗口与进度呈现（0.2.0）

批量处理是低频功能，不常驻大块进度区域、不挤占画布。工具栏始终有 Tasks；空闲只显示按钮。启动批处理或导出后自动打开居中模态Tasks窗口，约900px，最大90vw/80vh，可调整大小。关闭/收起仅影响显示，不停止任务；运行时顶部保留 `Tasks ◌ F/T` 和细进度线，随时可再次展开。任务结束保持窗口开合状态，短暂通知结果；失败保留错误标记，不抢焦点。历史任务折叠，当前任务默认展开。

窗口利用完整空间分组展示：任务类型/状态/开始时间/已耗时；完整8px条形进度与成功/失败/跳过/剩余数量；只读模型/设备计划；worker编号、设备、当前图片、单图耗时及加载/空闲/停止状态；失败图片和错误；导出后端路径；取消、恢复待处理图片及View logs。

扫描、设备探测、加载模型和最终导出元数据阶段使用不定进度动画和具体阶段文字。处理阶段显示可确定的真实进度，不根据时间编造百分比。单图耗时持续变化，可判断任务仍在执行；不伪造剩余时间预测。导出目前是目录副本，没有压缩归档阶段，进度按已检查图片数推进，最后显示Writing export metadata。取消导出删除本次未完成目录，已有成功导出不动。

日志窗口记录模型/设备/worker和任务阶段事件；批处理组件展示精确运行进度；统计栏展示项目审核状态。三者共享 project_id/job_id 等标识但不从日志文本推算数量。

取消导出还需覆盖进入packaging阶段后及最终元数据写入完成前的边界；此时仍删除本次未完成目录，不能忽略取消并报告complete。

## 11. YOLO 与训练导出

默认工作投影为 YOLO。labels_seg 是工具约定，Ultralytics 默认从 images 映射 labels；仅在 YAML 添加 labels_seg 不能保证训练器采用。

导出 detection 或 segmentation 的独立 images/labels/data.yaml，分割输出将工作 labels_seg 转为标准 labels，禁止混放 box 与 polygon 行。保持多级路径，首版复制图片。检测默认只导显式 box，可选临时从 mask 推导，仅作用于导出，不回写工作项目。

导出校验类别、路径冲突、划分及未分配实例，可生成连续类别 ID 副本而不改工作项目。未标注不能当负样本，只有 explicit_empty 或完成标注的图像可纳入对应任务。

YOLO 多边形对孔洞/不连通实例可能有损，输出告警及报告；COCO RLE 支持无损导出。内部始终保留原始 mask、实例 ID 和提示历史。

空RLE不算有效分割实例；无其他有效实例且未明确确认背景时跳过图片，不能把遗留空mask导出为未经确认的负样本。

## 12. CLI、构建与部署

单一 console script 使用 tyro，仅提供用户命令，依用途排序：serve；segment、detect、boxes-from-masks；ui；models list、doctor、docs。帮助开头解释启动、批处理、分机部署和诊断用途，不增加开发子命令。CLI help 不加载模型；模型配置与项目标签分离，模型只从本地读取，禁止自动下载和推理时自动安装依赖。

```bash
uv sync
uv run annodesk serve --project /data/dataset --open
annodesk serve --host 0.0.0.0 --port 8765
annodesk serve --api-only --host 0.0.0.0 --port 8765
annodesk ui --port 8080 --api-url http://gpu-host:8765
npm ci --prefix frontend
npm run build --prefix frontend
uv build
```

默认127.0.0.1:8765，仅 --open 打开浏览器，端口冲突报错。serve 同源提供 API+已编译 UI；serve --api-only 仅后端；ui 只提供已编译资源和运行时 API 配置，不加载推理。数据集始终在后端机器，客户端本地图片需上传/同步/挂载后使用。

API /api/v1，info 返回应用/协议版本和能力；运行时 /ui-config.json 指定 API base，不写死 localhost、不重新编译。图片/mask/缩略图使用 ID URL，通过 HTTP 获取；跨源支持 CORS 和无 credentials 请求。SSE/任务轮询恢复按 job ID，不丢持久状态。

Hatchling 打包。web_dist 作为 package data 随 wheel/sdist 发布，普通运行者不需 Node。仓库跟踪匹配的预构建资源，干净 clone 后 uv sync 即可打开 UI；前端开发使用 Node/npm lock，通过 npm ci 和 npm run build 执行依赖安装、类型检查与构建，不属于发布CLI。uv sync 不隐式安装 Node 或 npm。发布 CI 先重建前端并检查资源版本，再 uv build，并在新环境安装 wheel 验证。安装目录只读或任意 cwd 均正常。

### 12.1 本地模型配置与无界面分割

仓库提供 models.json；命令行 --models-config 优先，其次 ANNODESK_MODELS_CONFIG、当前目录 models.json、仓库默认、wheel 内置默认。JSON 按segmentation/detection分组，各自定义default_model及models数组；旧顶层扁平格式继续兼容，但禁止混写。每项含 id、name、backend(sam/sam2/mobile_sam/sam3)、source（模型最终一级目录，不配置 checkpoint 文件名）。ID 唯一，默认 ID 必须存在。

source 只填写最终一级模型文件夹，不填写 pt/safetensors 文件，也不提供 checkpoint 字段。展开环境变量和 ~ 后统一两步查找，不识别 repo ID 类型：先相对 JSON 目录 resolve 并检查 is_dir；不是目录则检查 $HF_MODELS/source（HF_MODELS 已设置时）。绝对路径直接检查目录，缺失报错，不剥离根路径后回退。repo ID 与普通相对目录的查找规则相同；本地同名文件不视为目录。

适配器在已选目录内自动查找兼容 .pt 权重，先按 backend 的已知命名匹配；无已知命名时仅接受唯一 .pt。没有兼容权重或多个候选均报错，不根据文件缺失再次换目录。safetensors-only 的 HF 目录暂不被当前 Ultralytics 适配器支持，页面明确显示不可用。配置每个 source 只包含一个模型。禁止 URL 和自动下载；推理禁用库联网/自动安装选项，Python 推理线程审计网络连接和下载/安装进程。辅助资源缺失也直接报错。

GET /api/v1/models 无需打开项目，返回配置条目、默认 ID、本地可用性、解析路径、错误、文本能力；页面模型选择器从此加载，可 Reload 配置及可用性。选择缺失模型时明确报错。GET /api/v1/project 在未打开项目时返回 200 null，避免把正常初始状态记录成 409；依赖项目的实际操作仍可返回 409。

annodesk segment --project /data/dataset --models-config ./models.json --model <id> 同步处理已有 YOLO 框，不启动 UI 或 HTTP 服务。默认模型来自 JSON，跳过已有 mask、锁定对象及 Excluded 图片；逐图保存到 labels_seg 与内部 RLE，保留 detection 框及类别 ID。中断后再次运行跳过已成功结果；失败明细写入 .annodesk/segment-report.json，单图失败退出码为1，配置/启动失败为2，取消/中断为130，成功为0。输出待人工复核，不自动标为 Approved。

### 交互细化：赋类、提示和品牌图标

Class palette 为日常赋类入口；顶部 Classes 为名称、颜色、ID 管理入口。选中框或 mask 后可直接点左侧类别，或按 C 打开带搜索的类别选择器，以 ↑↓ 选择、Enter 确认、Esc 取消。画布选择模式下双击实例也可打开；右侧提供 Change class 按钮。赋类沿用自动保存/撤销，不修改几何，锁定实例不可赋类。1/2/3 仍用于图片审核状态，不与类别快捷键混用。

- 区分了模型 ID、模型目录和执行设备；禁止把 --devices 再当物理编号解析。

### 对称分组配置

### 部署角色与地址说明

serve在数据集/推理电脑运行，同时托管API与网页。GPU服务器serve绑定0.0.0.0后，本机浏览器直接访问http://服务器IP:8765即可，无需本机ui。serve --api-only同样拥有数据集、标注存储和推理，仅省略网页；ui可在本机或独立网页主机运行，默认本机浏览器访问http://127.0.0.1:8080，浏览器直接连接api_url指定的远端API。ui不代理数据集、不读取/保存本机项目、不上传图片到远端推理节点。

CLI的serve（含--api-only）/ui概述、project、api_url及open帮助须说明运行电脑、浏览器地址、127.0.0.1和监听地址的区别。user guide区分同机、服务器serve、本机ui+服务器serve --api-only三种方式，推荐普通远程浏览器使用服务器serve。共享/同步/挂载只能使服务器能读写文件，不冒充尚未实现的本地项目+远程纯推理架构。

0.2.2最终CLI入口删除独立api命令，统一为serve --api-only；不保留别名。该模式不托管网页，仍拥有项目读写和推理，与--open同用时在创建日志/服务前报错。内部HTTP应用的mode=api保持不变，不影响API协议。


Mask 转检测框支持每侧外扩：pixels 为每侧像素数；ratio 为当前 mask 紧包围框宽/高的比例（UI 用百分数，CLI/API 用小数，0.1=10%）。min 勾选时覆盖模式，横/纵方向分别取像素与比例外扩量的较小值；最终裁剪到图片边界。默认 0，不改变原有紧框。右侧实例属性和批任务提供相同设置，本次会话共用；任务启动后冻结配置。CLI 使用 --box-padding-mode pixels|ratio、--box-padding-pixels、--box-padding-ratio、--box-padding-min。仅创建缺框/显式重算、锁定保护及审核语义不变。撤销/重做放在独立“历史”工具组；“编辑 SAM 提示”提供直接进入提示选择范围的入口。框缩放允许独立调整宽高，不默认保持比例。


交互补充：普通选择与SAM提示选择保持分开。V与普通选择按钮共用入口，退出提示选择范围；在输入框中输入v不触发工具快捷键。同一实例名称再次点击切换展开/收起并保留选择；几何图标始终选中对应目标并展开。文字提示工具在画布内显示绝对定位输入浮层，自动聚焦输入，关闭或Esc返回普通选择，不改变画布尺寸。工具光标区分普通选择、箭头尖端附工具标记（检测框为蓝色实框、SAM提示框为琥珀色角框加号、正负点及文字各有标记）和手形平移（拖动时闭手），Space临时平移松开/窗口失焦后复原；缩放控点仍显示方向光标。属性开关固定在画布工具栏最右侧、紧邻右栏，视图控制保持同组，左侧模型/推理控件空间不足时在自身区域横向滚动。

实例搜索框上方提供“清空本图标注…”：确认窗口显示实例数量，删除目标包含其框/mask/全部提示；默认保留锁定实例，可明确勾选包含锁定实例。操作一次撤销，保留tags、备注、项目类别与排除状态，Detection/Segmentation审核回到pending，清除两任务的explicit_empty，不自动认定为已确认负样本。清理替换当前编辑上下文、使未完成画框及在途推理/候选失效；确认窗口绑定图片和项目会话，切图/切项目/导航时关闭，不得误清其他图片。


当前交互默认：Auto-segment默认勾选，可手动关闭。只在切入未排除、Segmentation=pending且存在可用分割模型/依赖的图片时，自动补全可见未锁定检测框的缺失mask，不覆盖已有mask、不处理已审核图片；Auto-detect仍默认关闭。文字提示浮层默认最大640px宽、五行多行输入，可竖向扩展，Enter换行、Ctrl+Enter/⌘Enter预览；不改变画布尺寸。

批任务前端轮询仅在项目ID/会话实际改变时清空任务列表；同一项目的元数据更新不得重置任务与统计。任务首次完成时刷新元数据和当前标注，后续完成状态轮询不重复触发刷新。批量Start自动保存与预检，Preview scope为可选入口，详见assisted-boxes扩展。


导出交互增补：Export打开统计确认窗口，选择任务、YOLO/COCO、include_pending及后端新目标目录。默认仅ok，uncertain/excluded始终跳过；pending须明确加入，有效实例或explicit_empty规则不变。自动保存后调用只读/export/preview，不物化导入记录，显示total、四种审核状态、eligible、各类skip及invalid明细；修改配置/目标后重新计算，确认前不启动任务。零eligible或invalid禁止确认。确认传入输出路径及源signature，执行前持项目锁重验，过期确认失败。源signature包含任务/格式/审核选项、类别、图片路径/尺寸/mtime、内部标注及外部投影指纹，不含输出路径。默认私有导出目录，指定目录支持绝对/相对项目根路径，禁止工作数据集内其他目录与覆盖已有目录。导出失败/取消只删除本次新建输出；复用已有输出前仍检查取消，取消时保留已有数据集。成功记录实际exported/skipped、文件SHA256清单及项目导出历史；源及选项一致且输出清单/校验和完整才提示已导出并复用，指定不同新目录可重新复制。历史旧版无清单输出不自动复用。导出为目录，无浏览器下载。三项图片级操作移至实例搜索框上方一行，使用短标签及完整tooltip，几何缺失/锁定状态决定禁用；Auto-detect默认关闭。

导出统计不显示Reviewed汇总层；图片总数下为同级的Not reviewed、Approved、Needs review和Excluded。预计导出数单独展示，由任务、审核筛选及有效标注共同决定。无效输入未能读取审核状态时计入总数及无效明细，不虚构审核分类。确认按钮固定在窗口底部，统计内容独立滚动。

导出跳过明细在存在跳过图片时默认展开，只显示非零原因计数及最多100张图片的相对路径/原因，超出显示已展示/总跳过数。无当前任务有效实例且explicit_empty未确认的图片归为no_annotations，即使包含未审核标注也不能作为负样本导出；用户需补标或明确确认无目标。


管理界面统一为居中临时模态窗口：Classes、Tags、Models、Tasks、Logs、Statistics、Shortcuts，以及批量、导出和确认对话框；内容内部滚动，关闭后继续标注。画布、左右常驻面板及画布内文字提示浮层保留原布局。窗口打开期间工作台快捷键不得误改图或标注；关闭Tasks/Logs不停止后台任务或日志写盘，后台更新不抢焦点重新打开窗口。可停靠常驻侧栏为未来设计，本轮未实现。

图片审核：无当前任务有效几何时仍允许pending/uncertain及excluded；新设为ok必须有该任务标注，或先明确设置explicit_empty。前端按钮与1快捷键共用检查，服务端拒绝新增空批准及移除批准结果/无目标确认后仍保留ok的保存；对旧版已存在的无效ok记录不做隐式重标。取消空图的无目标确认时，该任务ok退回pending。导出四类状态下各自缩进显示no_valid_annotations数量：无该任务几何且未确认无目标；这是所属状态的子集，不与状态数量相加，也不计入有效负样本。总量和跳过明细规则不变。

空图尝试通过审核时，使用居中提示窗口替代顶部错误条，说明补标/确认无目标要求；“打开图片属性”只展开并定位确认项，不自动勾选或批准。“继续标注”关闭提示。后台轮询、统计及日志连接错误仍采用现有非打断式反馈；本轮未将所有错误统一为弹窗。


非阻断全局错误使用顶部居中固定悬浮通知条，不进入布局，不推移画布、图片列表或统计。保留关闭及未保存时的重试保存，长消息可展开详情，不自动关闭，不强制转移焦点；后台轮询不反复弹出对话框。空图批准等明确被阻止的操作使用前述居中提示窗。

Export summary与Skipped images均按四种审核状态分组，状态下缩进列出“无有效标注且未确认无目标”的子集。主统计子集包含该状态所有图片；Skipped子集只包含实际跳过图片，不与父级相加。无效输入无法读取状态时，另列“审核状态无法读取”，不伪造四类归属。API增加skipped_by_state及skipped_no_valid_annotations；各状态跳过数含unknown之和等于total-eligible，底层skip原因优先级不改变子集归属。

“Confirm no objects for this task / 确认此图片在当前任务下没有对象”固定在图片审核按钮正下方、tags/备注之前，使用浅色强调区，始终占据固定位置。确认与批准独立，不自动设为Approved；提示窗继续定位该项。

Objects/实例区域始终展开，不提供整区折叠入口；列表、搜索、图片级操作及区域分隔条保持可见。各标注目标的操作详情默认收起，即使挂载时已有选中对象也不自动展开；点击名称或几何图标按既有规则展开，再次点击名称可收起。

统计子项界面短标签统一为“No valid annotations / 无有效标注”；悬停说明仍为无该任务有效标注且未明确确认空背景，统计规则不变。

导出文件级明细（图片路径、跳过原因及无效输入错误）置于独立滚动区域，高度上限min(240px,30vh)，支持键盘滚动，滚动不串到父窗口；审核状态统计和已展示/总跳过数量保留在区域之外。仍至多列出100张跳过图片，不用长文件清单撑开导出窗口。

跳过图片清单每行只显示“相对路径 — 简短原因”；no_annotations使用“No valid annotations / 无有效标注”，不再重复追加确认空背景的完整解释。
